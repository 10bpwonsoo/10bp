# 입력 수집 구조 (2026-11-25~)

Daily Snapshot 의 가격 · 기사 입력을 모으는 부분을 분석(Claude 세션)에서 떼어 냈다. 수집은 Python 만으로 돌고,
분석은 수집 폴더를 읽기만 한다. 2026-11-25 아침 Yahoo 429 로 스냅샷이 통째로 멈춘 뒤 바꿨다.

- 실행: `python -m marketpulse.collector run` — [수집 대상 목록](data-sources-inventory.md)
- 설정: `marketpulse/config/collection.yaml`
- 테스트: `tests/test_collection.py`

## 1. 2026-11-25 에 확인한 것

| 확인 항목 | 결과 |
|---|---|
| 수집 라이브러리 | `yfinance` · `curl_cffi` · `requests` 를 쓰지 않는다(설치돼 있지 않다). 표준 라이브러리 `urllib` 로 차트 API 를 직접 부른다 |
| endpoint | `https://query1.finance.yahoo.com/v8/finance/chart/<심볼>?period1&period2&interval=1d&events=div,split` |
| 보내는 식별자 | `User-Agent: MarketPulseAI/0.1 (+저장소 주소)` — 브라우저를 흉내 내지 않는다 |
| 429 를 낸 쪽 | Yahoo 엣지. 응답 헤더 `server: ATS`, TLS 인증서가 Yahoo 것(실행 환경의 프록시가 만든 응답이 아니다) |
| 429 본문 | `Too Many Requests` (19바이트, `text/html`) |
| Retry-After | **없다** — 언제 풀리는지 공급처가 알려 주지 않는다 |
| 단일 요청 | 9분 넘게 아무 요청도 안 보낸 뒤의 첫 요청 하나도 429 |
| 같은 요청 반복 | 같은 심볼 · 같은 헤더 요청을 8초 간격으로 10번 → 200 이 4번, 429 가 6번 섞여 나왔다 |
| 다른 User-Agent | `curl/8.5.0` 으로는 본문이 `Edge: Too Many Requests` (23바이트) — 식별자 단위로 거르는 **다른** 429 다 |
| 다른 날 같은 클라이언트 | 같은 코드 · 같은 식별자로 오후에는 220여 요청이 막힘 없이 끝난다(11/20~11/24 기록) |

읽는 법:

- **클라이언트 문제가 아니다.** 같은 클라이언트가 같은 시각에 200 과 429 를 번갈아 받고, 다른 시간대에는 전부 통과한다.
- **이 세션의 호출량 때문이 아니다.** 한동안 쉰 뒤의 첫 요청도 막히고, 간격을 8초로 벌려도 결과가 요청마다 달라진다.
- **남는 설명은 '여러 사용자가 같이 쓰는 클라우드 출구 주소에 걸린 Yahoo 쪽 한도'** 다. 요청마다 결과가 갈리는 것은 출구 주소가 여럿이고
  그중 일부만 한도에 걸려 있을 때의 모습과 맞는다. 다만 **출구 주소 자체를 이 환경에서 볼 방법이 없어 직접 확인하지는 못했다** — 관찰과 맞는 설명일 뿐 확정이 아니다.
- 브라우저 식별자를 흉내 내면 통과하는지는 **확인하지 않았다**(공급처의 제한을 피해 가는 일이라 이 저장소 규칙으로 하지 않는다).
  `yfinance` 는 최근 판에서 `curl_cffi` 로 브라우저 TLS 지문을 흉내 내는데, 같은 이유로 들이지 않았다.

## 2. 기존 구조의 문제

1. **Yahoo 전체 성공이 스냅샷의 전제였다.** 수집(`archive fetch-inputs`)이 세 묶음을 통째로 받아 끝에 한 번 저장했다. 중간에 끊기면 처음부터였다.
2. **429 를 받으면 그 자리에서 잤다.** 45 → 90 → 180초를 자며 같은 요청을 되풀이했고(합 20분), 그동안 다른 공급처 계열도 못 받았다.
3. **쉬는 상태가 메모리에만 있었다.** 프로세스 · 컨테이너가 다시 뜨면 잊고 처음부터 다시 두드렸다(11/25: 8분 간격 대기 작업이 2시간 넘게 반복, 재시작 뒤 또 반복).
4. **대체 경로가 사실상 없었다.** Yahoo 심볼 136개 중 대체가 설정된 것은 20개 남짓이었고, 그 대체(Stooq)는 이 실행 환경에서 연결이 끊긴다. 종목 · AI 바스켓은 Yahoo 하나뿐이었다.
5. **'못 받음' 과 '받았지만 낡음' 을 가르지 않았다.** 공급처가 최신 일봉 없이 응답한 계열을 사람이 눈으로 찾아 뺐다.
6. **수집 진행이 세션 임시 폴더에만 있었다.** 수집과 분석이 한 세션에 묶여 있어 다른 곳에서 받아 넘겨줄 통로가 없었다.

## 3. 바뀐 구조

```
[수집 — Python 단독]                       [전달]                    [분석 — Claude 세션]
python -m marketpulse.collector run   →   data/inputs/<날짜>/   →   build_day.py status|context|full|partial
  · 계열 하나 받을 때마다 저장(checkpoint)    (같은 기기면 그대로,          · 입력 상태 판정(OK · STALE · MISSING)
  · 공급처별 회로(파일에 남는다)              다른 기기면 git 가지         · FULL → 확정 저장 / PARTIAL → 따로 저장 · regime 보류

```

### 3.1 공급처 Circuit Breaker — `marketpulse/adapters/breaker.py`

- **공급처(호스트) 전체**에 건다. 계열 하나가 막히면 그 공급처의 나머지 계열도 같은 쉬는 시간을 지킨다.
- 공급처가 `Retry-After` 를 주면 **그 시간만큼** 회로를 연다(임계를 기다리지 않는다).
- 없으면: 연속 실패 1 · 2번째 뒤 공급처 전체가 10 · 20초 쉬고, **3번째에 회로를 연다.** 쉬는 시간은 5분에서 시작해 다시 열릴 때마다 2배(→ 10분 → 20분 → … 최대 60분).
- 회로가 열려 있는 동안에는 **요청을 보내지 않는다.** 그 계열은 다음 공급처로 넘어가고, 넘어갈 곳이 없으면 결측이다.
- 쉬는 시간이 끝나면 시험 요청 하나를 보낸다(half-open). 통과하면 닫고, 막히면 2배로 다시 연다.
- 상태는 `.marketpulse_state/provider_breaker.json` 에 원자적으로 쓴다(벽시계 기준). **다시 뜬 프로세스가 남은 쉬는 시간을 그대로 이어 간다.**
- 무엇을 받았는지도 남긴다 — 상태 코드 · `Retry-After` 원문 · 본문 앞부분. `python -m marketpulse.collector breaker` 로 본다.

임계를 1이 아니라 3으로 둔 이유: 11/25 처럼 같은 요청이 200 과 429 를 번갈아 받는 날에는 429 한 번으로 5분씩 쉬면 통과할 수 있는 요청까지 버린다.
한두 번은 짧게 쉬고 다시 보내고, 세 번 연달아 막히면 '지금은 정말 막혔다' 로 본다. 값은 `collection.yaml` 의 `breaker` 에서 바꾼다.

### 3.2 수집기 — `marketpulse/collector/`

| 명령 | 하는 일 |
|---|---|
| `python -m marketpulse.collector run` | 오늘(KST) 입력 수집. 받은 계열은 건너뛰고 빠진 것만(이어 받기) |
| `… status` | 받은 것 · 빠진 것 · 공급처별 성공률 · 회로 상태 · FULL / PARTIAL 판정 |
| `… news` | 기사(RSS)만 한 번 더 받아 합친다 — 07:30 KST 뒤에 부른다 |
| `… inventory --md docs/data-sources-inventory.md` | 수집 대상 · 공급처 순서 목록을 다시 만든다 |
| `… breaker [--reset 호스트]` | 회로 상태. `--reset` 은 사람이 풀린 것을 확인했을 때만 |
| `… run --publish` · `… pull` | 다른 기기와 주고받기(3.4) |

- 계열을 하나 받을 때마다 `checkpoint/<묶음>/<id>.json` 에 쓴다. 죽었다 다시 떠도 받은 것은 다시 요청하지 않는다.
- 한 번 실행은 `run.budget_min`(기본 25분)까지만 돈다. 회로가 풀리는 시각이 남은 예산 안이면 그때까지 기다렸다 이어 받고, 밖이면 **기다리지 않고 끝낸다.**
- 종료 코드: `0` 다 받음 · `75` 일부 남음(다음 시도 가능 시각을 출력) · `73` 같은 폴더에서 이미 도는 중.
- 받았지만 마지막 봉이 빠진 계열(STALE)은 다음 실행 때 한 번 더 받아, 새로 받은 쪽의 마지막 봉이 더 늦을 때만 바꾼다.
- 대체 공급처에서 받은 계열은 직전 수집분과 겹치는 날짜의 값을 대조한 뒤에만 쓴다(차이 중앙값 2% 초과면 버린다 — 단위 · 수정주가 · 통화 불일치). 직전 수집분의 값은 오늘 입력에 들어가지 않는다.
- 전날 수집 폴더를 오늘 수집에 다시 쓰려 하면 거절한다.

### 3.3 입력 상태 판정과 PARTIAL — `marketpulse/archive/input_status.py`

| 상태 | 뜻 | 처리 |
|---|---|---|
| OK | 기준 시각(07:30 KST)에 나와 있어야 할 마지막 봉까지 있다 | 쓴다 |
| STALE | 받았지만 마지막 봉이 그보다 오래됐다 | **계산에서 뺀다**(결측) — 전날 종가를 오늘 종가처럼 쓰지 않는다 |
| MISSING | 못 받았다 | 결측 그대로(0 · 보간 · 전날 값 없음) |

- '나와 있어야 할 마지막 봉' 은 공급처별 공개 시각 규칙(`archive/pit.py`)으로 따진다. FRED 금리는 규칙상 하루 늦는 것이 정상이라 STALE 이 아니다.
- 휴장일은 `collection.yaml` 의 `market_holidays` 로 가린다. 한 시장의 계열이 **전부** 같은 날에 멈춰 있으면(5개 이상) 휴장으로 본다(`CLOSED_SUSPECT` — 보고에 따로 적는다).
- 메모리 현물 · 계약가처럼 주 · 월 단위로 손으로 넣는 파일은 날짜 간격으로 가리지 않는다(엔진이 자기 규칙으로 본다).

핵심 계열(`gate.must` · `gate.core`)이 모자라면 그날은 **PARTIAL** 이다.

| | FULL | PARTIAL |
|---|---|---|
| 저장 위치 | `data/archive/YYYY/MM/<날짜>.json` (불변) | `data/archive/partial/<날짜>.json` |
| 날짜 목록 · 화면 | 그날 스냅샷으로 보인다 | 목록에 없다 — 화면은 직전 확정 스냅샷 그대로 |
| 공식 regime | 그날 판정 | **보류** — 직전 확정 스냅샷의 값 그대로(`meta.regime_decision`) |
| history · regime 상태 로그 | 한 행씩 쓴다 | **쓰지 않는다**(복사본 위에서 계산) |
| 기사 · 태그 · 메모리 가격 · 거시 | 쓴다 | 쓴다 |
| 나중에 | — | 정상 입력을 받으면 `build_day.py … full` 로 확정본을 새로 만든다. PARTIAL 파일은 `superseded/` 로 옮겨 남는다 |

`build_day.py <날짜> <inputs> full` 은 판정이 PARTIAL 이면 저장을 거절한다(종료 코드 3). 확정 저장본과 history 는 어떤 경로로도 덮어쓰지 않는다.

### 3.4 다른 기기에서 수집하기 (컨테이너 의존 없애기)

11/25 의 429 는 클라우드 출구 주소에서 생겼다. 집 · 사무실 PC 나 따로 둔 서버에서는 같은 요청이 대개 통과한다. 수집기는 그런 곳에서 돌도록 만들었다.

**준비 (한 번)**

```
git clone <저장소>            # 또는 이미 받아 둔 폴더
cd 10bp
python -m venv .venv
.venv\Scripts\pip install -e .          # Windows   (Linux · macOS: .venv/bin/pip install -e .)
```

환경변수(값은 어디에도 출력되지 않는다): `FRED_API_KEY`(금리 · 크레딧 — 없으면 그 계열은 결측), `KRX_API_KEY`(한국 지수 · 종목의 공식 경로 — 선택), `TWELVEDATA_API_KEY`(선택).

**Windows 작업 스케줄러** — `tools/collector/run_collector.bat` 를 화~토 06:40 에 한 번, 실패(75)면 30분 뒤 다시:

```
schtasks /Create /TN "MarketPulse Collector" /TR "C:\경로\10bp\tools\collector\run_collector.bat" /SC WEEKLY /D TUE,WED,THU,FRI,SAT /ST 06:40
schtasks /Create /TN "MarketPulse Collector retry" /TR "C:\경로\10bp\tools\collector\run_collector.bat" /SC WEEKLY /D TUE,WED,THU,FRI,SAT /ST 07:10
schtasks /Create /TN "MarketPulse Collector news" /TR "C:\경로\10bp\tools\collector\run_collector.bat news" /SC WEEKLY /D TUE,WED,THU,FRI,SAT /ST 07:31
```

두 번째 줄은 첫 실행이 다 받았으면 받을 것이 없어 바로 끝난다(이어 받기). 세 번째는 07:30 이후 기사를 채운다.

**Linux 서버 (cron, 서버 시간대가 KST 일 때)**

```
40 6 * * 2-6  cd /srv/10bp && tools/collector/run_collector.sh
10 7 * * 2-6  cd /srv/10bp && tools/collector/run_collector.sh
31 7 * * 2-6  cd /srv/10bp && tools/collector/run_collector.sh news
```

**넘겨주기** — 스크립트는 수집 뒤 `--publish` 로 결과를 git 가지 `collector-inputs` 에 올린다. 그 가지는 **항상 커밋 하나**다(매번 새 뿌리 커밋으로 바꾼다 —
하루 2~3MB 입력이 저장소 이력에 쌓이지 않는다). 작업 가지 · 작업 폴더는 건드리지 않는다. push 권한은 그 기기의 git 설정을 그대로 쓴다.

**읽는 쪽(Claude 세션)** — `python -m marketpulse.collector pull` 로 그 날짜 결과를 `data/inputs/<날짜>/` 에 꺼낸 뒤 `build_day.py … status` 로 본다.
빠진 계열이 있으면 같은 폴더에 `collector run` 을 돌려 그것만 받는다. 그 날짜 결과가 가지에 없으면 다른 날짜 것으로 대신하지 않는다.

> 이 가지에 올리는 것은 공개 시세와 기사 목록뿐이다. 키 · 토큰은 수집 결과에 들어가지 않는다.

정리: **이 실행 환경 안에서는 미국 주식 · ETF · 선물 · 한국 종목의 당일 종가를 Yahoo 말고 받을 길이 없다.** FRED 는 금리 · 크레딧은 채우지만 주가지수 · 유가 · 환율은 늦게 준다.
그래서 Yahoo 가 막힌 날 이 환경만으로는 PARTIAL 이 된다. 당일 FULL 을 지키려면 (가) 수집기를 다른 망에서 돌리거나(3.4), (나) Twelve Data · 증권사 API 키를 넣어야 한다.

### 4.1 KRX 공식 Open API (2026-11-25 추가 · 실제 응답으로 확인)

- 호출: `GET https://data-dbg.krx.co.kr/svc/apis/<서비스>?basDd=YYYYMMDD`, 헤더 `AUTH_KEY`. 응답 `OutBlock_1` 에 **하루치 전 지수(전 종목)** 가 온다 — 기간 조회가 없다.
  그래서 날짜마다 한 번씩 부르고, 받은 날짜는 `.marketpulse_state/krx_openapi/` 에 남겨 다시 부르지 않는다(처음 한 번은 서비스마다 300여 번 · 그 뒤로는 하루 한 번).
- 확인한 응답(basDd=20261124): 지수 `BAS_DD · IDX_CLSS · IDX_NM · CLSPRC_IDX · FLUC_RT …`, 종목 `ISU_CD`(6자리) `· ISU_NM · TDD_CLSPRC …`. 값은 쉼표 없는 문자열.
  코스피 5006.03(+6.32%) · 코스피 200 778.68 · 코스닥 665.88(+4.79%) · KRX 반도체 9372.73 · 코스피 200 변동성지수 58.45 · 삼성전자 189400 · SK하이닉스 1158000.
- 오류 두 가지: `401 Unauthorized Key` = 키 자체가 틀림 · `401 Unauthorized API Call` = 그 서비스의 'API 이용신청' 승인이 없음.
- 쓰는 서비스(모두 승인됨): `idx/kospi_dd_trd` · `idx/kosdaq_dd_trd` · `idx/krx_dd_trd` · `idx/drvprod_dd_trd` · `sto/stk_bydd_trd` · `sto/ksq_bydd_trd`.
- 키: 이 저장소의 클라우드 환경에서는 네트워크 시크릿(호스트 `data-dbg.krx.co.kr` · 헤더 `AUTH_KEY`)이 넣는다 — `collection.yaml` 의 `providers.krxapi.key_via_network_secret`.
  PC · 서버에서는 환경변수 `KRX_API_KEY`. 어느 쪽도 없으면 첫 요청의 401 뒤로 그 실행에서는 부르지 않는다.
- 어디에 쓰이나: **코스피 · 코스닥 지수와 한국 종목의 두 번째 공급처**다. Yahoo 가 실패하거나, 11/25 처럼 **마지막 봉을 비워 둔 채 답하면** 수집기가 이쪽에서 받는다.
  받아들이는 조건은 ① 같은 날 Yahoo 에서 받은 계열과 겹치는 날짜의 값이 맞고 ② 끝난 봉이 더 있을 때다. 그 계열의 이력은 KRX 것으로 통째로 바뀐다(`meta.source = krxapi:코스피`).
- 연결하지 않은 것: 코스피 200 · KRX 반도체 · V-KOSPI. 지금까지 한 번도 수집된 적이 없는 계열이라(Yahoo 1봉 · KRX 화면 403) 켜면 그날부터 판정에 새 입력이 들어간다 —
  `sources.yaml` 줄 끝 주석에 설정만 적어 뒀다. 사용자 결정 뒤에 켠다.
- 쓸 수 있는 때(PIT): 날짜 00:00Z + 9h — 한국장은 그날 06:30Z 에 끝난다.
- 종목 종가는 수정 전 종가라 배당 · 분할 조정이 없다 — Yahoo 수정종가와 수준이 다르면 대조에서 걸러진다.

대체 공급처를 더할 때 확인하는 것(공급처마다 다르다):

| 항목 | Yahoo | Stooq | Twelve Data | FRED |
|---|---|---|---|---|
| 종가 기준 | 수정종가(배당 · 분할) | 분할 조정(배당은 확인 필요) | 분할만 조정(기본) | 공표값 |
| 봉 시각 | 그 시장 개장 시각(UTC) | 날짜만(00:00Z) | 날짜만(00:00Z) | 관측일(00:00Z) |
| 쓸 수 있는 때 | 봉 시각 + 7h(유럽 9h · VIX 14h · 선물은 뉴욕 17:00) | 미국 +22h · 한국/일본 지수 +9h · 그 밖 +24h | +22h | 다음 평일 22:00Z |
| 통화 · 단위 | 상장 통화 | 상장 통화 | 상장 통화 | 금리 % · OAS %(×100 → bp) |

수준이 조금씩 다를 수 있어(수정 기준 차이) **한 계열의 이력은 한 번에 한 공급처에서 통째로 받는다** — 공급처를 섞어 이어 붙이지 않는다.
어느 공급처에서 왔는지는 계열의 `meta.source`(`stooq:nvda.us` 등)와 `collect_status.json` 에 남는다.

## 5. 한계 — 아직 안 된 것

- PARTIAL 스냅샷은 저장되지만 **대시보드 화면에는 나오지 않는다**(기존 UI 를 바꾸지 않았다). 그날 화면은 직전 확정 스냅샷이고, PARTIAL 의 내용은 보고와 파일로만 본다.
- 회로 상태 · 수집 진행은 디스크에 남아 프로세스 · 컨테이너 **재시작**을 넘긴다. 컨테이너가 **회수돼 새로 만들어지면**(저장소를 새로 받는 경우) 남지 않는다 — 그때는 처음부터 받는다.
- Stooq · Twelve Data 경로는 코드와 테스트(형식 · 공개 시각 · 대조)는 있지만 실제 응답으로 돌려 보지 못했다.
- 휴장일 달력은 2027년 2월까지 확인된 날만 들어 있다. 빠진 휴장일은 STALE 로 보인다(안전한 쪽으로 틀린다).
