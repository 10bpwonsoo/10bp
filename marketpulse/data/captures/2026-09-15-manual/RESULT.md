## 방법
- 계정 크레딧이 0이라 LLM 추출 API 를 쓸 수 없었다. 대신 이 세션(Claude)이
  RSS 로 실제 수집된 기사 60건을 직접 읽고 28건을 손으로 태깅했다
  (`manual_tags.py`). 나머지 32건은 사내공시·프로모션 등 테마와 무관해
  제외했다 — 룰 추출기도 태그를 못 다는 기사들이다.
- 시장 가격 데이터는 무료 공급자(Yahoo/GitHub)에서 새로 받았다. 이것도
  API 크레딧이 아니다.
- `build_manual_snapshot.py` 가 build_intelligence() 의 추출 단계만 이
  수기 이벤트로 바꿔치기하고, 나머지(시장 판정·테마·괴리·영향경로·알림·
  온도계)는 엔진의 순수 함수를 그대로 재사용한다 — 로직은 새로 안 짰다.
- 화면에는 `extractor="manual"` 로 정직하게 남는다. `llm_status` 도
  `disabled` 다 — 자동화된 API 호출이 아니었기 때문이다.

## 정직하게 밝히는 한계
1. **이것은 자동화된 파이프라인이 아니다.** 매 틱 재현되지 않는다.
   실사용에는 여전히 API 크레딧이 필요하다.
2. **Oil/Rates 테마의 sentiment 축 판단이 애매하다.** 유가·금리 상승
   기사를 "시장 전체에 부담" 으로 읽어 sentiment 를 음수로 매겼다. 이는
   event_extractor.py 시스템 프롬프트의 인플레이션 예시("물가 둔화 확인"
   → 감성 +)와 같은 축(거시적으로 좋은/나쁜 뉴스)을 따른 것이지만,
   themes.yaml/lexicon.yaml 의 "테마가 강해지는 방향이 + (유가 급등 기사는
   Oil 테마에 +)" 관례와는 반대로 읽힐 수 있다. 실제 자동화된 LLM 호출이
   같은 프롬프트로 어느 쪽을 택할지는 검증하지 못했다 — 이 판단은 이
   세션의 해석이지 API 응답이 아니다.
3. **Oil·Semiconductor 괴리의 절반은 데이터 결측 탓일 수 있다.** KRX 가
   막혀 있어 삼성전자·SK하이닉스 관련 한국 지표(KRX_SEMI, KOSPI200 일부)가
   빠졌다. 뉴스가 말하는 반도체 급락이 가격 지표에 온전히 반영되지 못해
   "괴리" 로 잡혔을 가능성이 있다 — 내러티브와 가격이 정말 어긋난 것과,
   가격 쪽 데이터가 불완전한 것을 구분해야 한다.
